# Build "Forge" CLI - TypeScript Stack Scaffolding & Enforcement Tool

## Context

We're building a CLI tool called `forge` that scaffolds and enforces conventions for a TypeScript stack optimized for AI-assisted development. The goal is to eliminate decisions so AI doesn't drift.

The key insight: Claude Code reads CLAUDE.md automatically. We use this as a **hook** — imperative instructions that tell Claude it MUST use the forge CLI commands.

## The Stack This CLI Supports

- **Frontend**: TanStack Start (file-based routing, Vite-based, SSR-ready)
- **Backend**: Convex (real-time database, functions, no separate API)
- **Styling**: Tailwind CSS + shadcn/ui
- **Linting/Formatting**: Biome
- **Language**: TypeScript (strict mode)

## CLI Tech Stack

Build the CLI using:
- **pnpm** - package manager
- **Node** - runtime
- **tsx** - run TypeScript directly in dev
- **tsup** - bundle for distribution
- **Citty** - CLI framework (modern, from UnJS ecosystem)
- **Handlebars** - templating for scaffolds
- **fast-glob** - file system scanning for validation
- **picocolors** - terminal colors
- **consola** - logging (from UnJS ecosystem)
- **oxc-parser** - fast AST parsing for import validation

## Commands to Implement

### 1. `forge init <project-name>`

Creates a complete project with:
- TanStack Start configured
- Convex initialized
- Tailwind + shadcn/ui configured
- Biome configured with strict rules
- Base folder structure
- TypeScript strict mode
- Base providers (Convex, etc.)
- **CLAUDE.md with imperative instructions (THE HOOK)**

### 2. `forge add:feature <name>`

The main command. Creates a full vertical slice:

convex/features/<name>/ ├── schema.ts ├── queries.ts ├── mutations.ts └── index.ts

src/features/<name>/ ├── components/ │ └── index.ts ├── hooks.ts └── index.ts

app/routes/<name>/ ├── index.tsx └── $id.tsx


Also:
- Auto-registers schema in `convex/schema.ts`
- Updates barrel exports

### 3. `forge check`

Validates project structure. Fails if rules are broken. Run in CI/pre-commit.

Rules to enforce:
1. **Feature structure**: Every feature has required files
2. **Component location**: Components only in `src/features/*/components/` or `src/components/`
3. **Hook location**: Hooks only in `src/features/*/hooks.ts` or `src/hooks/`
4. **Thin routes**: Route files in `app/routes/` can ONLY import from `src/features/` or `src/components/`, no business logic
5. **No cross-feature imports**: `src/features/X/` cannot import from `src/features/Y/`
6. **Feature parity**: Every `src/features/X` should have `convex/features/X`
7. **No orphan files**: No loose `.tsx` files outside the structure

Validation Rules for forge check

Rule 1: Feature Structure

Every src/features/<name>/ must contain:

components/index.ts
hooks.ts
index.ts
Every convex/features/<name>/ must contain:

schema.ts
queries.ts
mutations.ts
index.ts
Rule 2: Thin Routes

Parse files in app/routes/. They should:

Only have imports from ~/features/, ~/components/, ~/lib/, @tanstack/react-router, convex/react, or @convex/_generated/
Not define functions other than the route component
Not contain more than ~50 lines (warning threshold)
Rule 3: No Cross-Feature Imports

Parse files in src/features/<name>/. They should not import from src/features/<other>/ or ~/features/<other>/.

Rule 4: Feature Parity

Every src/features/<name> should have a corresponding convex/features/<name> and vice versa.

Rule 5: Component Location

.tsx files (except route files) should only exist in:

src/features/*/components/
src/components/
Rule 6: Hook Location

Files with use*.ts pattern or containing hooks should only be in:

src/features/*/hooks.ts
src/hooks/

Template Loading Strategy

Templates live in templates/ directory and are read at runtime:

// src/utils/template.ts
import Handlebars from "handlebars";
import { readFileSync } from "fs";
import { join, dirname } from "path";
import { fileURLToPath } from "url";

const __dirname = dirname(fileURLToPath(import.meta.url));
const templatesDir = join(__dirname, "../../templates");

// Register helpers
Handlebars.registerHelper("camelCase", (str: string) => {
  return str.replace(/-([a-z])/g, (g) => g[1].toUpperCase());
});

Handlebars.registerHelper("pascalCase", (str: string) => {
  const camel = str.replace(/-([a-z])/g, (g) => g[1].toUpperCase());
  return camel.charAt(0).toUpperCase() + camel.slice(1);
});

Handlebars.registerHelper("kebabCase", (str: string) => {
  return str.replace(/([a-z])([A-Z])/g, "$1-$2").toLowerCase();
});

export function renderTemplate(templatePath: string, data: Record<string, unknown>): string {
  const fullPath = join(templatesDir, templatePath);
  const templateContent = readFileSync(fullPath, "utf-8");
  const template = Handlebars.compile(templateContent);
  return template(data);
}
Key Implementation Notes

CLAUDE.md is critical — It's the hook that makes Claude Code use the CLI. Generate it in forge init.
Use consola for logging — it has nice formatting built-in
Use oxc-parser for fast AST parsing when validating imports
Templates are read at runtime — they live in templates/ and are included in the package
Use async/await throughout — modern patterns only
Exit with code 1 on forge check failures so CI fails
Use process.cwd() to resolve paths relative to where the CLI is run
